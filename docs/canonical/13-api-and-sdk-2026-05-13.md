## 2. Auth (NV-AUTH-HEADER-001)

**One canonical SDK auth header:**

```
X-API-Key: <NYV_SDK_KEY_{NSP|NSPM|NSI|NSA|NSM|NYM|JRX}>
```

**Bearer fallback** is supported for legacy clients only:

```
Authorization: Bearer <NYV_SDK_KEY_…>
```

CI guard `nv-check-auth-header.sh` blocks any PR that introduces a new
accepted header (e.g. `X-Nyv-Token`). All Console JWT-only paths use
`Authorization: Bearer <jwt>`; SDK paths accept both shapes via
`dualSdkOrJwt`.

### 2.1 The seven SDK keys + their scopes

| Code | Product                          | Audience                  | Scopes (live DB row) |
|------|----------------------------------|---------------------------|----------------------|
| NSP  | Nyayasiddhi Professional™        | Law firms                 | `agents:read`, `agents:execute`, `documents:read`, `documents:write`, `research:read`, `usage:read` |
| NSPM | Nyayasiddhi Professional Mobile™ | Law-firm mobile           | `agents:read`, `agents:execute`, `documents:read`, `documents:write`, `research:read`, `usage:read`, `voice:read`, `voice:execute` |
| NSI  | Nyayasiddhi Institutional™       | Enterprise legal depts    | `*` (wildcard) |
| NSM  | Nyayasiddhi Ministry™            | Government agencies       | `*` (wildcard) |
| NSA  | Nyayasiddhi Academy™             | Legal education           | `agents:read`, `agents:execute`, `documents:read`, `research:read`, `translate:write`, `usage:read` (**no `documents:write`** by design) |
| NYM  | Nyayamitra™                      | Citizens                  | `agents:read`, `agents:execute`, `documents:read`, `documents:write`, `translate:write`, `consumer_intake:write`, `usage:read` (**no `research:read`** by design — citizens go through consumer-intake) |
| JRX  | JurisX™                          | Cross-jurisdiction tools  | `*` (wildcard) |

A 403 `Insufficient scope` response is **always intentional** — it means
the caller's SDK key does not own the scope listed in the route
definition (e.g. NYM hitting `/gateway/research/query`). Pick a SDK key
whose scopes match, or upgrade the row in `sdk_app_api_keys.scopes`.

## 3. v5 vs non-v5 routing (NV-API-CONTRACT-001)

There is exactly one routing rule:

| Prefix | Purpose | Auth | OpenAPI snapshot |
|---|---|---|---|
| `/api/nv/…`  | **Stable contract.** All SDK integration goes here. Frozen by `nv-check-api-contract.sh` — additions allowed, removals fail CI. | `dualSdkOrJwt` (X-API-Key OR Bearer JWT) | yes |
| `/api/nv5/…` | **Internal / Console-only.** `/api/nv5/orch/*`, `/multimodal`, `/voice`, `/workflows`, `/doc-ai`, `/legal-pipeline`, `/compliance`, `/internal`, `/gov`. Behind feature flags (`isNyvFeatureOn(...)`). Not for third-party SDK callers. | Bearer JWT only (Console proxy) | not exposed |

**Rule:** if you are an external SDK integrator, you call **only**
`/api/nv/…` URLs. If you find yourself reaching for `/api/nv5/`, you are
probably writing Console code, not SDK code.

### 4.7 Orchestrate — full 17-step pipeline (POST, X-API-Key)

The single entry point that exercises the entire safety ring (PII redact
→ guardrails → agent select → LLM cascade → guardrails → audit chain).

`POST /api/nv/orchestrate`

```json
{
  "prompt": "Summarize this contract dispute in 2 sentences: …",
  "agentId": "summarizer",
  "jurisdiction": "IN",
  "taskType": "summarize",
  "mode": "sync",
  "enableMemory": false
}
```

Response:

```json
{
  "success": true,
  "data": {
    "content": "…final answer…",
    "model": "gemini-2.5-flash",
    "latencyMs": 14732,
    "tokens": { "prompt": 421, "completion": 189, "total": 610 },
    "ledger": { "actionId": "cam_…", "hash": "0x…" },
    "guardrails": { "pii_redacted": 0, "policy_violations": 0 }
  }
}
```

### 4.8 Streaming — Server-Sent Events (SSE)

| Path | Notes |
|---|---|
| `POST /api/nv/orchestrate/stream` | SSE token stream of the same 17-step pipeline. Headers: `Content-Type: text/event-stream`. |
| `POST /api/nv/stream/agui`        | AG-UI streaming (Console-side; SDK-callable). |

Wire format (one event per token chunk, terminated by `data: [DONE]`):

```
event: token
data: {"delta":"Summary","model":"gemini-2.5-flash"}

event: token
data: {"delta":" of the contract…","model":"gemini-2.5-flash"}

event: done
data: {"latencyMs":14732,"tokens":{"total":610},"actionId":"cam_…"}

data: [DONE]
```

**Note on `EventSource`**: the W3C `EventSource` API is GET-only and
cannot send a request body or custom auth headers. Because the
`/api/nv/orchestrate/stream` endpoint is a `POST` (it carries the
prompt + agent context in the body) and authenticates with `X-API-Key`,
SDKs **must** use `fetch` + a manual SSE parser. `EventSource` is only
appropriate for the GET-style Console paths under `/api/nv/stream/agui`
when carrying a session cookie, e.g.:

```js
// Console-only, GET, cookie auth — never use for SDK POST streams.
const es = new EventSource('/api/nv/stream/agui?topic=…', { withCredentials: true });
```

Universal `fetch` + SSE example (works in browser, Node 22, RN, Deno):

```js
const res = await fetch(`${BASE}/api/nv/orchestrate/stream`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-API-Key': process.env.NYV_SDK_KEY_NSP },
  body: JSON.stringify({ prompt, agentId: 'summarizer', jurisdiction: 'IN', taskType: 'summarize' }),
});
const reader = res.body.getReader();
const decoder = new TextDecoder();
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  decoder.decode(value).split(/\n\n/).forEach(handleEvent);
}
```

## 5. PII redaction & RAG (where they fire automatically)

Every `/api/nv/orchestrate*` and `/api/nv/intelligence/*` call passes
through:

1. **PII redaction** — names/emails/phones/addresses/IDs are
   tokenised with `NV_PII_ENCRYPTION_KEY` before any LLM sees the text,
   and de-tokenised on the way back.
2. **Guardrails** — prompt + response policy enforcement.
3. **RAG / GraphRAG** — when the route accepts a `kbId` / `namespace`
   / `useRag: true` flag, the orchestrator retrieves from
   `rag_namespaces` (per-org, vector + GraphRAG fusion via RRF).
4. **Audit chain** — every call is hash-chained to the IronLedger
   (`nv_audit_logs` + `nv_cam_actions`) before the response returns.

You do **not** need to call the redaction / RAG / audit endpoints
yourself. They are wired into the safety ring.

## 8. Errors

All error responses follow:

```json
{ "success": false, "error": "<short>", "message": "<human>", "request_id": "req_…" }
```

| Status | Meaning | What to do |
|---|---|---|
| 400 | Missing/invalid body | Fix the payload. Body schema is in §4. |
| 401 | Missing or invalid SDK key | Set `X-API-Key`. Verify against `gateway/info`. |
| 403 | Insufficient scope | Pick a SDK key whose scopes match (see §2.1). |
| 408/504 | Upstream LLM timeout | Retry with the same request id. The server runs a 12-level cascade; one provider can be slow. |
| 429 | Per-org rate limit hit | Back off per `Retry-After` header. Limits live on `nv_platform_rate_limiter`. |
| 500 | Internal | Capture `request_id` and report. |

**Rate limit policy (Replit dev + EC2 prod-dev):**
- Free tier: 60 req/min/key
- Pro tier: 600 req/min/key
- Enterprise / wildcard scope: 6,000 req/min/key
- The dev-only `NV_E2E_BYPASS=1` env var disables all gates for the
  duration of UAT (production guard intact).

## 9. Streaming clients — full minimal RN/web/Node samples

(See §4.8 for the wire format and the EventSource caveat.)

```js
// SDK POST stream (any platform) — fetch + manual SSE parser
const res = await fetch(`${API}/api/nv/orchestrate/stream`, {
  method: 'POST',
  headers: { 'X-API-Key': key, 'Content-Type': 'application/json' },
  body: JSON.stringify({ prompt, agentId, jurisdiction, taskType }),
});
const reader  = res.body.getReader();
const decoder = new TextDecoder();
let buf = '';
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += decoder.decode(value, { stream: true });
  const events = buf.split(/\n\n/); buf = events.pop();
  for (const ev of events) handleSseEvent(ev); // parse `event:` + `data:` lines
}

// Console GET stream — EventSource is acceptable here (cookie auth, no body)
const es = new EventSource('/api/nv/stream/agui?topic=…', { withCredentials: true });
```

## 10. Verification — 7×20 E2E (2026-05-13, final)

`scripts/nv-sdk-platform-e2e.mjs`: **139/140 PASS, 55/56 real-LLM PASS.**
The one-row delta is an intermittent `WARN_EMPTY_CONTENT` from
`sarvam-30b` on a single NSA `/orchestrate` invocation. `sarvam-30b`
has been removed from both `SOLO_CHEAP` and `INDIC_LEGAL` cascades; the
residual hit is a stale model-tier-router selection path tracked as a
known model-tier defect, not an SDK-contract regression. The gateway
returned 200 with a valid model + latency envelope; only the body was
empty.

**Latency profile (real-LLM only):** p50 = 6.7s, p95 = 28.5s, max = 52.6s.

Full machine-readable report: `/tmp/nv-sdk-e2e-report.json`.

The 17-step orchestrate pipeline (PII redact → guardrails → agent
select → LLM cascade → guardrails → audit chain) is verified end-to-end
on every key, including the IronLedger hash-chain entry.

Failure inventory (zero auth / wiring / orgId / shape / timeout failures):

| Code | Endpoint | Cause | Fix |
|---|---|---|---|
| soft | `/orchestrate` (NSA, jurisdiction=IN) | model-tier-router still selected `sarvam-30b` despite removal from cascade sequences; model returned empty content | retry; tracked as residual model-tier-router defect |

This is not a contract regression and **does not block the EC2 cutover.**

## 11. EC2 cutover note

Replit dev and EC2 prod-dev expose the **same** `/api/nv/*` contract.
Once this doc is published, the only swap an integrator makes between
dev and prod is the base URL (§1). Headers, payloads, error shapes,
streaming format, and SDK-key scopes are identical.

**Do not deploy to EC2 without explicit user "GO".** This doc is
designed to be the integrator's reference *before* and *after* the
cutover.
